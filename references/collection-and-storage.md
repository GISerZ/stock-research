To collect the latest completed market day manually, run this PowerShell command from the workspace at or after 15:00 Beijing time on a trading day. It uses the same collector, snapshot directory, and completed-day deduplication as the scheduled task:

```powershell
$stockSkill = Join-Path $env:USERPROFILE '.codex\skills\stock-research'
python (Join-Path $stockSkill 'scripts\collect_sentiment.py') --market --output-dir .
```

The command prints the saved market snapshot's absolute path. On a partial collection it also prints gaps and returns a nonzero exit code; inspect the saved JSON rather than treating that exit code as no snapshot. Use the Python interpreter configured for the scheduled task if `python` resolves to a different environment. The task itself does not need to be started for a manual run.

For a single-stock deep dive, run this command from the workspace where `research/` belongs, replacing the example ticker:

$stockSkill = Join-Path $env:USERPROFILE '.codex\skills\stock-research'

Use the working Python interpreter in your current environment; the skill's `.venv` may point to a missing interpreter. Install the pinned packages in `requirements-evidence.txt` into that interpreter if needed. For a justified peer and a verified valuation reset event, add flags such as `--peer '300666=半导体靶材及零部件业务' --valuation-reset-date 2026-07-15`. Repeat `--peer` for more companies. For sentiment evidence, optional `--social-review-file PATH` supplies manually checked public posts, and `--cross-market-file PATH` supplies the selected international references and their source-backed local trading dates. Their formats and time gates are in `sentiment-framework.md`. When either review is unavailable, preserve its explicit missing state in the report.

### Optional stock analysis coverage

The stock CLI adds `analysis_coverage = summarize_analysis_coverage(packet)` after both review files have been processed, immediately before its final save. The function in `sentiment_stock.py` reads only the in-memory packet: no requests, original-source authentication, scores, rating decisions or changes to `source_results`, `completeness` or existing exit codes. It is not added to market snapshots or intermediate market-backfill saves.

| Summary field | Saved meaning |
|---|---|
| `window_status`, `required_trade_dates` | `available` only with a calendar-verified, distinct ascending five-day list ending on the packet's trade date and no collection failure; otherwise `unavailable` and an empty list, without guessed dates. |
| `heat_history` | `required_days=5`, distinct in-window dates with a positive integer saved rank, `valid_days`, `missing_trade_dates` and `data_status=recorded/missing`. Current top-100 or Tonghuashun ranks cannot fill this history. |
| `market_fields` | `rising/falling/flat/suspended/limit_up/limit_down/failed_board`, each with the same day-coverage fields; count distinct requested dates having an original observation with `status=ok` and a non-null value. A saved numeric zero counts; the whole market day need not be complete. |
| `news_candidates` | Exact saved list length as `saved_count` (not an independently deduplicated news population), `verification=candidates_only` and a limitation note. Zero does not establish no news or completed review. |
| `social_review`, `cross_market` | Copy only the original `status` / `selection_status`; missing status is `missing`. Review reasons, samples, references and time/coverage limits remain in the original fields. |
| `missing_fields`, `limits` | Missing list/review inputs and interpretation limits; no inferred source success or rating permission. |

With a known window and a recorded empty list, saved valid-day count is zero and all five dates are missing. If the window or the relevant input list is unavailable, day counts and missing dates are `null`; absent news input has `saved_count=null`. These are counts of saved coverage, not proof that the market had no activity. Original observations remain subject to existing producer/loader checks; the summary does not re-verify their financial truth or source finality.

The early `_completed_date` calendar-failure save also receives an unavailable summary, preserving `collection_status=failed`, null `as_of_trade_date`, `partial`, its diagnostic directory and exit code 2. A calendar failure returned by `collect_stock_day` follows the final stock save with the same unavailable-window rule. Market complete-reuse, non-trading-day skips and market calendar diagnostics retain their existing paths and behavior. Schema v1 still allows old stock snapshots with no summary; readers use original fields manually rather than regenerating or rewriting them. An additional review attachment cannot change a previously saved snapshot or its summary. A future collection may create a new version because the optional summary is new; old versions remain intact.

The collector prints an absolute path under `research/evidence/`. Read that JSON and cite its path and collection time in the report. The index reuses extracted page text without extra network requests or OCR. Recognized complete headings guide region ordering: financial topics prefer notes/supplement pages and management discussion prefers its own section, then other readable pages, accounting policies and contents. Within a rank, earlier PDF pages come first. Detected contents do not set a section; a page without text resets the inherited region. Unknown headings keep candidates without invented section ranges. This is a text heuristic, so residual contents, cross-references and policy hits remain possible; the order is not financial confidence.

Resolve a candidate through its parent document's `pdf_path`, `pdf_sha256`, `source_url`, title and publication date in the exact saved packet. `pdf_path` and `text_path` stay workspace-relative; from a report in `research/`, a PDF page link is `evidence/documents/<actual-sha256>.pdf#page=<PDF-page>`. Do not reuse that report-relative string as a packet path. `page` always counts from the first PDF page, including covers; printed page labels are not generated. Record a printed label separately only after reading it. Open the original page and relevant neighboring pages, reconcile table rows/columns, units, date and entity, and save the verification before adopting a financial input. Do not copy a candidate directly into verified workpaper inputs or the key-facts table.

`extraction_status=ok` and source `ok` retain their original meaning of available text, not full-page coverage or verified disclosure. If only some pages have text, `source_results[].detail` and `issues` identify the number of pages with no extractable text; these may be blank or scanned and need original-page review. An all-textless PDF retains `text_unavailable`, its original PDF and issue, with no new index; extraction exceptions retain their failure diagnostics. A readable document with `section_candidates=[]` has no keyword hit in its extracted text. A legacy document without this field has no generated index. Neither condition proves the topic or risk absent.

Keep the original PDF hash, link, page count, extracted text and transaction `excerpts`; the new field is optional within schema v2. A future collection saves a new versioned packet under the existing rules and does not rewrite historical packets or hash-addressed PDFs/text to add the index. This index does not reconstruct tables or extract verified amounts. For manual acceptance, use a selected real annual report to open candidate PDF pages, compare body results with contents/policy hits, and inspect a textless or partly scanned document. Success is traceable navigation, not hits for all seven topics; no bulk historical reprocessing is needed.
